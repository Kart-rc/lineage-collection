Three engines, one trust chain

How the platform collects element-level data lineage across thousands of repositories — and why an edge's confidence comes from independent mechanisms agreeing, never from any single signal.

The one-line rule: EventBridge routes, SQS buffers, Step Functions coordinates, Fargate analyzes, S3 preserves, DynamoDB controls, Neptune traverses — and a human, or an audited auto-publish policy, approves.

Why three engines

Each engine answers a different question

Static analysis answers what the code says. The LLM answers what static analysis could not parse. Runtime answers what actually executed. They never overrule each other — they corroborate or conflict, and both outcomes are recorded.

"It never guesses." Deterministic parsing of the repository at an exact commit digest.

CHECKOUT → DETECT/ROUTE → PARSE → AST-WALK → CONFIG-RESOLVE → RESOLVE(URN) → EMIT

How it collects

  • Shallow-clones at the digest with per-run read-only credentials; the workspace is destroyed after the run.
  • Deterministic parsers — sqlglot dialect matrix, dbt manifest, OpenAPI/proto — plus tree-sitter AST rule packs for Python, Java/Kotlin, JS/TS, Go.
  • Every edge carries file:line plus an AST path: no edge without proof.
  • Determinism is CI-enforced — same (digest, ruleset, config) must produce a byte-identical evidence file.

What it can't do, honestly

  • Dynamic names, reflection, and unparseable types become residue — each with a reason code, the file span, and nearby facts. Nothing is silently skipped.
  • That residue list is the contract that drives the LLM engine: it defines exactly what inference is allowed to touch.
  • Only its parser-exact edges qualify for auto-publish — the highest-trust class in the platform.

"It proposes, never gates." Inference restricted to SCA's residue, behind a four-stage guardrail chain.

TIER → CHUNK ≤8k → CONTEXT → CACHE → CALL → GUARDRAILS → EMIT | REJECT

How it collects

  • Three tiers: residue on cache miss, registered no-grammar files on baseline/nightly runs, and nightly verification samples for calibration. PR-path requests are rejected by design.
  • Chunks along AST boundaries (span + enclosing function + imports + config keys, ≤ 8k tokens) — never whole-repo prompting.
  • SCA's own facts and known URNs are injected as context, and the prompt records which facts were provided.
  • Cache keyed on (chunk digest, prompt version, model id): unchanged code is never re-billed. Hit rate ≥ 90% is a launch gate.

How it's kept honest

  • Guardrails in strict order: schema validates → the citation exists in the digest → the URN resolves → budget holds. First failure persists a typed reject.
  • Zero unvalidated edges reach the merge; free text is forbidden.
  • "I can't resolve this" is a first-class answer that feeds the runtime watch list — not an error.
  • LLM-only edges are capped at the lowest confidence band and can never gate a PR or auto-publish.

"It proves execution, not intent." Observation of instrumented integration-test runs — names and shapes, never values.

GRANT → READY → OBSERVING → DRAIN → CLOSED (COMPLETE | INCOMPLETE)

How it collects

  • No session, no ingestion: grants are signed, scoped to (repo, environment), and expire with the test budget.
  • Four emitters: OpenTelemetry auto-instrumentation, a custom lineage.emit() SDK, a Spark OpenLineage listener, and a Dask plugin. Only the SDK and Spark may assert element-level lists.
  • Records dataset names, operations, counts, and schema fingerprints — deterministic hashes of field names and types, never data values.

The hard boundary

  • Production is denied twice — once at IAM, again in the validator — and a weekly live probe must fail to inject.
  • Only sessions that close COMPLETE corroborate at full weight; an incomplete session never promotes confidence.
  • Absence of runtime evidence never demotes an edge — not seeing something is not evidence it's gone.

The confidence lab

Confidence is not a score anyone assigns — it is derived from which independent mechanisms assert the same edge. Toggle the engines and watch the band the merge would compute.

LOWESTLLM alone — a plausible guess, clearly labeled as one
SINGLEone non-LLM mechanism
MEDIUMa mechanism + LLM agreement
HIGHcode says it and execution confirms it
HIGHESTall three mechanisms agree

Two rules keep this honest: conflicts are kept verbatim and sent to review — never averaged into a middle band. And dataset-level runtime containment is tracked as separate corroboration; it never changes the band itself.

The guarantees

Invariants the whole chain leans on

Each of these is enforced by a specific component, not by convention — and most are backed by a CI gate, a replay drill, or a live probe.

Nothing vanishes silentlyEvery trigger becomes a run, a dedupe, or a quarantine record with a reason.
A guessed identity is a defectEvery name resolves against a pinned catalog snapshot or is quarantined with candidates. Zero matches or two equal matches both stop the line.
Evidence is write-onceS3 objects are checksummed and immutable; the graph and every projection can be rebuilt from evidence alone, and a rebuild drill must show zero divergence.
The band is re-derivableEvery confidence band can be recomputed from the provenance on the edge — there is no hidden judgment.
Absence never demotesAn edge only decays after three consecutive silent analyses by the mechanism that asserted it — and it goes stale, never deleted.
Publication is fencedThe visible graph pointer advances only under a monotonic fencing token; a stale writer can never win, and rollback is a pointer move, never a rewrite.

Design vs. today

What's actually proven right now

The mechanism above is fully specified and mostly implemented — but on a real repository today, collection is effectively one-signal: the static engine. That is a recorded, deliberate state, not an accident.

Proven locally

  • Static engine with element-level Java/Spring Data JPA + Python coverage, validated on pinned real checkouts of Spring Petclinic — 15 edges on the official repo, 9/9 prototype-alignment on the 8-module microservices repo.
  • URN resolution, orchestration, classification, consolidation bands, and the review lifecycle all pass local acceptance; drift against the prototype expectation breaks the build.
  • Intake, evidence stores, fenced publication, and the PR gate pass on synthetic events, with live AWS behavior still to be exercised.

Designed, not yet real

  • The LLM gateway is interface-only — its skip and no-fabrication contracts pass, but no real model is ever called.
  • Runtime observation exists as local contracts; no collectors are installed, and running it isn't yet exposed on the CLI or collections API.
  • Consequence: no real edge can currently reach the high-agreement bands — the ones declared safe for automated impact gating. Closing that starts with putting runtime verification on the product path.
