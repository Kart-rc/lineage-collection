Contracts own the critical path
Decision: T1 owns the contracts lib, L01 resolver and L08 store client as its first deliverable — freezes F1/F2 land in week 1, kept deliberately small.
• T1 pairs with T4 on the L08 client to remove the single-owner bottleneck.

GATE · W3: another team deploys a service through the pipeline using the client libs
2
CodeQL — criteria-gated, not a bet
Decision: tree-sitter + sqlglot is the default critical path. CodeQL runs as a week 2–6 spike on the Java/Kotlin pack, behind the same ScaEvidenceFile contract.
• Pass criteria, all three: median analyze ≤ 10 min on the standard Fargate size · byte-identical replay across two runs · licensing at 10k repos within cost policy.
• Either outcome, zero downstream change — L07 consumes the same evidence schema.
GATE · W6: go/no-go recorded as an ADR; loser kept as a non-blocking adapter
3
T3 sequenced so OTel never blocks launch
Decision: classification (L13) and the E2E harness come first — both sit on the launch path. The OTel slice starts M2 and targets staging corroboration by M4.
• Bands never require runtime evidence (absence never demotes) — an OTel slip moves corroboration post-launch, nothing else.
• Hard-deny probe ships with the validator, not after it — security is not deferred.
GATE · W8: skeleton E2E green (harness) · W13: probe paging · W17: bands lift in staging
4
Trust-chain tail scoped, staffed, signed
Decision: T4's charter explicitly includes L09 review, L10 fenced publication and a minimal L11 — review-flow SPA + lineage/impact query only, no dashboard polish.
• UAT reviewers recruited and trained by W10 on staging data.
• Governance sign-off on the auto-publish policy file scheduled W12 — it is a launch gate, so it cannot arrive late.
GATE · W8: manual publish through fencing · W12: policy signed · W16: reviewer UAT complete
5
Testing without a QA team
Decision: a test-ownership matrix replaces the workstream — unit + contract suites gate every PR in the owning team; T3 owns the shared harness, seeded repos and perf rigs; integration scenarios run nightly in staging; the drill calendar (replay, rebuild, DR, hard-deny) is owned by T1 with evidence retained. GATE · every milestone exit is a test artifact, not a status report.

QUALITY MODEL · NO SEPARATE QA PHASE (L16)
Testing strategy & exit gates
Forward-looking delivery plan from the component PRDs (L01–L16); dates and figures are targets. Normative production AWS view: docs/architecture/lineage-platform-target.md
UNIT
Lands with the code, gates every PR in every team. Property tests where the invariants live: merge idempotency + commutativity, fencing (an expired worker cannot win), resolver golden corpus, band matrix table-driven.
CONTRACT
Pacts on every freeze F1–F7 (EventEnvelope, resolve(), ScaEvidenceFile, ConsolidatedEdge, Proposal/Approval, pointer + manifest). Semver-pinned; a post-freeze change is a major bump with a migration note.
INTEGRATION
Hermetic staging, seeded repos with expected-lineage.json. Scenarios: incremental push end-to-end · baseline · conflict & correction round-trip · duplicate replay · redrive · replay/rebuild from S3 alone.
PERFORMANCE
intake ack ≤ 500 ms · 10k burst zero loss · SCA ≤ 10 min median · merge ≤ 60 s · publish ≤ 5 min · 1-hop query ≤ 2 s — measured under production-like load, not asserted.
UAT
Real reviewers on live proposals: approve, reject, correct end-to-end without leaving the SPA; quarantine triage → alias decision; engineers read a lineage + impact answer. Sign-off is the production-publish gate.
