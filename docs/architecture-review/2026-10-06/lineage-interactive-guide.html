03

Two checks can share one mistake.

Filter the evidence ledger. Method, independence, scope, and completeness are separate dimensions. None of these labels is a calibrated probability.

Corroborated ≠ independently verified. Runtime can genuinely execute code and reveal missed edges. What matters is the sensor and matcher: Python observes injected I/O; Java proxies enumerate entity fields; external sessions can carry independent evidence. Agreement under a coarse matcher is not proof of transformation equivalence. Preserve provenance rather than multiplying confidence scores.

Choose the acceptance scenarios to exercise

These fixed, fictional fixtures demonstrate denominator differences. They do not run an application, inspect this repository, or report achieved coverage.

Given / When / Then

Given: real isolated Spring, Kafka, Spark and table environments; pinned code/schema versions; independently reviewed gold; paid fixtures 1,250 + 750 minor units and cancelled 999.

When: invoke the public service, observe acknowledged publication, process a bounded offset interval, commit the table, query the downstream service.

Then: assert 20.00 in both sink and response, correct grouping/row-set behavior, and exact typed amount/filter/grouping mappings. The gold must not come from the annotations or SCA being tested.

Async attribution & loss gates

Retain span links plus Kafka cluster/topic/partition/offsets, writer/reader schemas, Spark application/query/run/batch IDs and sink commit. One trace ID alone is insufficient across fan-in, retries and replay.

Production capture fails open for business execution, with bounded buffers and explicit loss. CI fails closed on absent required evidence after a declared deadline. Complete delivery does not establish complete workload or field coverage.

Metadata only: never serialize method arguments, row values, secrets or customer payloads into lineage events.

Why an annotation or decorator is not value taint

A custom OTel event can declare that amount_minor → amount_major was executed under contract v2. An interceptor can observe method reachability and success. Neither proves the mapping declaration true, nor a later Kafka acknowledgement or table commit. Emit DECLARED_AND_EXECUTED provenance; independently validate expected typed edges and sink behavior. Async functions, generators, futures and lazy Spark plans need completion-aware instrumentation.

05

Accuracy needs a denominator.

Move the sliders in this fictional 100-edge oracle. The exercise shows why “we returned fewer wrong edges” can coexist with poor recall. These are teaching counts, not a repository benchmark.

Quality trade-off lab

Capture coverage and edge recall use different populations. The sliders deliberately vary them independently. A complete event transport window does not establish that every branch, field, or transformation was observed.

Also measure exactness

Exact-field accuracy: the entire typed dependency set matches the oracle. One correct edge does not rescue a field with a missing join control or a fabricated source.

Resolution coverage: fully resolved eligible output-field instances ÷ all eligible instances. Publish partial and unsupported counts.

Make the oracle independent

Use hand-reviewed typed graphs, engine-grounded checks, negative controls and held-out operator families. Score source, target, schema version, relation and scope.

Report supported-cohort and whole-estate recall separately. Unsupported and abstained cases remain misses in estate recall.

Proposed gates, not achieved results: a one-sided 95% lower confidence bound ≥99% precision, ≥95% recall and ≥90% exact-field accuracy for the supported cohort; 100% honest unknown/conflict labels on mandatory adversarial cases. Ratify the corpus, sample size and risk tolerance before promising these.
06

100,000 a day is the beginning.

Daily means hide bursts, dependency fan-out, and backfill. Change the assumptions. Every output is an arithmetic scenario, not measured throughput, a bill, or a production commitment.

Capacity & backlog simulator

Fixed assumptions: 3 × 50,000-byte envelopes/run; 10-minute burst; 0.5 CPU-sec/novel context + 0.02 CPU-sec/run; target utilization 60%; 180-day raw archive, 3:1 compression. Decimal GB/MB. Empty numeric inputs use the starting value; out-of-range inputs use the nearest allowed bound.

Show the equations and the limits
mean = executions_per_day / 86,400
live_burst = mean × burst_multiplier
backfill_rate = executions_per_day × backfill_days / 86,400
assertions_per_day = executions_per_day × fields × dependencies
raw_GB_per_day = executions_per_day × 3 × 50,000 / 1,000,000,000
cores = arrivals × (uncached_fraction × 0.5 + 0.02) / 0.60
backlog = max(0, arrivals − service_capacity) × 600
drain_seconds = backlog / (service_capacity − ongoing_arrivals)
  only when service_capacity > ongoing_arrivals

Backfill is spread over 24 hours, and remains at that rate during modeled draining. CPU is an assumed arithmetic minimum before redundancy, memory, I/O, JVM overhead and tail behavior. Canonical shape reuse changes graph growth, not the existence of execution evidence. The queue diagram uses separate burst/drain time scales for legibility. Rates must be benchmarked against observed artifact-size and degree distributions.

Do not write every repeated edge to Neptune

32 million run-level assertions/day at the starting scenario becomes 5.76 billion in 180 days. Archive assertion bundles and occurrence records; keep canonical, versioned dependency shapes in the graph.

Reader replicas do not remove the writer bottleneck. Profile graph materialization and traversal separately.

LLM cost is also review capacity

At 5% routing and 60% inference-cache hits: 2,000 requests/day. With 6k input + 1k output tokens, model cost is 12 × input-rate + 2 × output-rate per day, with rates per million tokens.

These are scenario assumptions, not vendor prices. Reviewing 500 candidates at 2 minutes each consumes 16.7 hours/day.

07

Defend the boundaries, not the diagram.

Answer out loud before revealing the response. A strong senior technical defense leads with the guarantee, the evidence, the failure boundary, and the next falsifiable test.

Senior / Distinguished Engineer rehearsal
SESSION 1 · 50 MINUTES

Own the implementation

  1. 5m: deliver the 90-second verdict twice.
  2. 15m: explain local vs AWS vs library-only paths.
  3. 15m: trace the running example and identify each missing proof.
  4. 10m: defend three reproduced correctness issues.
  5. 5m: write the next acceptance test for each.
SESSION 2 · 55 MINUTES

Attack the design

  1. 10m: define identity, scope and typed dependencies.
  2. 15m: run the failure scenarios without reading answers.
  3. 15m: change burst/backfill inputs and explain SLO failure.
  4. 10m: justify build / reuse / buy by architectural layer.
  5. 5m: record what evidence would reverse the decision.
SESSION 3 · 50–60 MINUTES

Survive the review

  1. 5m: state the decision and support contract.
  2. 30m: randomize the challenge questions; use 2–3m each.
  3. 10m: handle follow-up objections and one failure injection.
  4. 5–15m: score clarity, evidence and intellectual honesty.
